# 飞书周报提交

完成“定位周次 → 收集证据 → 起草 → 写入个人文档 → 登记链接 → 回读验证”的闭环。使用用户身份操作；不要把一次写入授权扩大为后续自动提交权限。

## 依赖

- 认证、身份或权限问题使用 `lark-shared`。
- 知识库节点定位使用 `lark-wiki`。
- 个人周报和小组登记页读写使用 `lark-doc`，并遵循其创建、更新、文档格式与回读流程。
- 只有周报事实需要从聊天或会议补证时，才分别使用 `lark-im` 或 `lark-meeting`；不要顺带发送消息或修改会议内容。

## 写入边界

执行飞书写操作前，确认当前用户请求已经明确要求提交、填写或更新。仅要求“看看怎么写”“给草稿”时只输出草稿，不写飞书。用户在同一请求中已经明确要求写入时，无需重复索要确认。

只修改目标个人周报和对应小组登记页。不要修改其他成员、行动项、会议纪要、群聊或无关文档。

## 流程

### 1. 确认入口、身份和报告对象

1. 获取周报总入口、报告人姓名、可能涉及的小组，以及用户希望提交的时间范围。能从当前上下文或入口页可靠解析时不要重复询问。
2. 使用 `--as user` 检查授权状态并读取总入口。
3. 从入口页或周次节点读取真实的周编号、起止日期和截止日期，不根据自然周自行猜测团队周编号。

### 2. 选择正确周次

- 用户报告已完成的上一周期工作，而当前周期刚开始时，默认选择最近一个已经完整结束的周次。
- 用户明确指定周次或日期范围时以用户指定为准，但若页面日期冲突，写入前指出冲突。
- 无法从页面确认周期时停止写入并询问，不把成果写入猜测的周次。

### 3. 定位小组和已有个人文档

1. 列出目标周次的直接子节点，按标题定位小组节点。
2. 同时读取小组登记页和其子节点：
   - 检查报告人在“成员”行的“周报”单元格；
   - 检查是否已有同名个人文档；
   - 记录小组页最新修订号和周报表格块标识。
3. 已有个人文档时优先更新，禁止创建重复同名文档。仅在没有个人文档时，在对应小组节点下新建空白文档，标题使用报告人姓名。

### 4. 收集证据并划清状态

优先使用当前周期内的个人产出、实验记录、群消息、会议纪要和已链接材料。每条内容归入以下一种状态：

- `已完成`：有可回链的产出、结果或验收证据。
- `部分完成`：已有阶段结果，但样本、链路、验证或交付尚未闭环。
- `下一步`：会议安排、待做实验或新方向，不能写成已完成。
- `阻塞/依赖`：说明影响、当前缓解方式、需要谁提供什么；未知原因明确写未知，不猜测。

区分事实、分析判断和计划。不要用会议数、沟通时长或“持续推进”替代产出；数值必须保留样本范围、时间点和适用边界。

### 5. 决定主责组和跨组呈现

报告人涉及多个小组时，只选择一个主责组承载完整周报：以本周期主要交付和主要评审关系判断，无法判断时询问用户。

- 主责组个人文档写完整内容。
- 其他小组个人文档只写与该组相关的跨组摘要、依赖和主周报引用，不重复全文。
- 如果团队惯例要求多个小组登记，分别登记各自个人文档；跨组文档必须链接主周报。

### 6. 起草并校验文档

个人周报至少覆盖：

1. 报告周期与总体状态。
2. 背景与问题。
3. 解决思路与实现。
4. 结果和证据。
5. 下一步计划、阻塞及协作需求。

按 `lark-doc` 的作者工作流选择 `workplace.weekly_report` 体裁，提交 Presentation Decision，初始化独占草稿，生成完整 XML，并运行 `docs +script --command parse`。只有 `data.assessment.status` 为 `passed` 才能写入。

专业缩写或内部代号首次出现时说明它是什么、不包含什么，以及它在本周报中的作用。保持具体、短、面向判断；不要把没有完成的安排写成成果。

### 7. 写入或创建个人周报

- 已有空文档：确认仅有标题且无评论或资源后，可用最新修订号写入完整候选内容。
- 已有正文：先读取完整内容，使用最小范围的 `block_replace`、`block_insert_after` 或 `str_replace` 更新；除非用户明确要求重建且确认无保留内容，否则不要 `overwrite`。
- 新建文档：使用小组知识库节点作为父节点创建，标题为报告人姓名。

写入结果必须满足 `result=success` 且无未处理 warning。随后完整回读个人文档，确认标题、周期、状态边界、文档引用和正文均已落盘。

### 8. 登记小组页面链接

1. 重新读取小组登记页，使用最新表格块标识和修订号；不要复用写操作前的旧标识。
2. 更新周报表格时保留表头、列宽、所有成员、已有链接和其他资源，只把报告人的空白或旧周报单元格改为个人周报引用。
3. 优先以一次 `block_replace` 替换完整周报表格，避免拆散表格结构。引用知识库个人文档时使用其 wiki 节点 token，而不是猜测 URL。
4. 每个小组页更新后立即按报告人姓名局部回读，确认该行显示正确文档标题和 token，且其他相邻成员仍存在。

### 9. 收尾与交付

删除 `lark-doc` 初始化产生的独占临时草稿目录，不删除用户原始材料。向用户返回：

- 实际提交的周次和日期范围；
- 主责组与跨组处理方式；
- 已验证的个人周报链接；
- 仍未关闭的事实缺口或权限问题。

只有“正文写入成功”和“登记页链接回读成功”两项都成立，才声明周报提交完成。
