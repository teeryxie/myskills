# 外部群消息诊断

外部群是至少包含两个飞书租户成员的群聊。租户是一个企业、学校或团队在飞书中的独立组织边界；应用权限、用户身份和机器人能力都受该边界约束。外部群不等于普通内部群，也不等于跨租户单聊。

## 已确认的官方限制

- `POST /open-apis/im/v1/messages` 支持 `user_access_token` 和 `tenant_access_token`。前者代表用户，后者代表应用机器人。
- 普通用户身份发送需要同时具备 `im:message` 和 `im:message.send_as_user`。
- 机器人要进入外部群并发送消息，应用必须是企业自建应用，开启并发布“对外共享”能力，机器人已加入目标群且有发言权限。
- 对外共享机器人在外部群调用 OpenAPI 时，官方支持 `im:message:send_as_bot`，但将 `im:message.send_as_user` 列为不支持。因此，不能用增加 OAuth scope 的方式让用户身份绕过外部群限制。
- 企业或团队需要满足飞书认证要求；管理员仍可在管理后台关闭应用的对外共享能力。

官方依据：

- [发送消息](https://open.feishu.cn/document/server-docs/im-v1/message/create)
- [机器人支持外部群和外部用户单聊](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/develop-robots/add-bot-to-external-group)
- [获取群信息](https://open.feishu.cn/document/server-docs/group/chat/get-2)

## 错误码含义

| 错误码 | 含义 | 处理 |
| --- | --- | --- |
| `230002` | 机器人不在目标群 | 将机器人加入群；外部群还需先开启对外共享 |
| `230018` | 群设置禁止当前操作 | 检查群禁言和发言人限制，联系群主或管理员 |
| `230027` | 缺少必要权限；可能是 scope、用户授权或外部群能力 | 检查授权一次；若授权完整且目标为外部群，转查对外共享与身份限制，不循环授权 |
| `230035` | 发送权限被群设置、屏蔽或租户沟通策略拒绝 | 检查群设置、接收方屏蔽和租户对外沟通策略 |
| `230038` | 跨租户单聊禁止通过该接口发送 | 不重试；改用允许的机器人对外单聊流程或人工客户端发送 |
| `232010` | 操作者与群不在同一租户 | 选择正确 profile/租户；若本来就是外部群，按对外共享流程处理 |
| `232011` | 当前用户或机器人不在群内 | 先加入目标群，再重试 |
| `232033` | 当前外部群不支持该操作者，或机器人未获外部群权限 | 为企业自建应用开启并发布对外共享，把机器人加入群；用户身份不能用该能力替代 |

## 诊断流程

1. 用 `lark-cli profile list` 确认组织 profile；用 `lark-cli whoami --profile '<profile>'` 明确当前代表的用户或机器人。多组织账号不得依赖 active profile 猜测。
2. 用 `lark-cli auth status --profile '<profile>' --verify --json` 和 `lark-cli auth check --profile '<profile>' --scope 'im:message im:message.send_as_user' --json` 检查用户令牌与 scope。不要输出 token、设备码或其他凭证。
3. 以用户身份执行最小只读群查询，确认 chat ID、群名、成员关系和 `external`。原生接口调用前先运行 `lark-cli schema im.chats.get`。
4. 写操作先使用对应官方 Skill 的 `--dry-run` 检查请求结构。`--dry-run` 不验证群成员关系、外部群能力或服务端租户策略，不能当作发送成功。
5. 正式发送保留 `--as user` 或 `--as bot`，并使用不超过 50 字符的幂等键。成功必须满足 `ok == true` 并返回 `message_id`；随后按业务 Skill 回读。
6. 若用户发送返回 `230027`：只在 scope 或授权确实缺失时重新授权一次。授权完成、令牌 ready、scope 已授予而同一外部群仍失败，结论是用户身份路径不受支持或被租户策略限制。
7. 若机器人只读查询返回 `232033`：检查应用是否为企业自建应用、企业/个人认证、版本中的对外共享开关、版本发布与管理员审批、管理后台是否禁用对外共享，以及机器人是否已加入群。
8. 完成配置后，先用机器人身份只读查询验证群可见性，再经用户确认发送身份后用 `--as bot` 发送。机器人发出的消息显示应用名，不得冒充用户本人。

## 复发条件与解决路径

以下情况会在其他外部群再次出现：切换到未配置的 profile；新应用没有对外共享；版本已配置但未发布或未审批；管理员关闭对外共享；机器人未加入新群；群限制机器人发言；用户试图用 `--as user` 调用外部群不支持的权限。

解决顺序是：选对 profile -> 验证身份与 scope -> 确认群为外部群 -> 开启并发布机器人对外共享 -> 将机器人加入目标群并确认发言权 -> 经用户确认改用机器人身份发送。若组织策略禁止对外共享，只能由目标租户管理员调整策略，或在用户明确同意后改用人工客户端/网页发送；CLI 不得声称绕过成功。
