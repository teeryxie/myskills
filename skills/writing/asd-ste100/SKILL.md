# ASD-STE100：简化技术英语

ASD-STE100 是欧洲航空航天与国防工业协会（ASD）制定的一套英语写作规范。它限制词义和句子结构，降低维修人员误读指令的风险。STE 是 Simplified Technical English，即“简化技术英语”。

本技能借用这套方法，改善 AI 代理、下游系统和非英语母语读者需要理解的英文文本，例如工具说明、错误消息、代理间指令和状态报告。

## 中文用户的语言约定

- 默认用中文说明规则、解释修改原因、报告保留项；用户指定其他语言时遵循用户要求。
- 英文输入的改写结果保持英文。默认只输出可直接使用的英文正文；不要自动把它翻译成中文。
- 用户要求“解释修改”“前后对照”时，表头和说明用中文，原句与改写句保留英文。
- 保留代码、命令、路径、接口字段、标识符及必要的英文专业术语。首次遇到理解结论必需的陌生术语时，用中文简要解释。
- 中文说明采用自然中文。英文的词数、时态、词性和短语动词限制只用于英文正文，不机械套用到中文。
- 用户仅要求中文润色或中文翻译时，按该请求处理；不要声称中文结果符合 STE 英语标准。

## 适用场景

- 代理输出、日志或工具说明过于冗长、术语密集或含义不明确。
- 文本将交给其他代理、翻译流程或非英语母语读者，误读有实际代价。
- 编写提示词、系统消息或工具说明，需要先消除歧义。
- 希望知道改写具体修复了哪些问题：此时提供前后对照。

STE 的表达刻意直白。创意写作、营销文案，以及以语气、微妙含义或说服力为核心的文本，不适合按这些规则改写。

## 两种模式

根据文本类型选择模式；用户明确指定时遵循指定。默认在内部完成选择，仅在用户要求规则分析或对照表时说明模式。

**严格模式（Strict）**：用于操作步骤、错误消息、工具或函数说明、代理间指令和安全相关文本。执行下述句子结构限制，并保持同一动作使用同一词语。词汇是否获官方批准，仍须查官方词典。

**参考 STE 模式（STE-flavored）**：用于 README、PR（代码合并请求）说明、更新记录和解释性文章。执行结构规则，包括句长限制、主动语态、简单时态及避免短语动词、分号、名词化表达和营销形容词；把词汇规则作为建议，不强制每个概念只能使用一个词。

## 来源与能力范围

上游依据 ASD-STE100 第 9 版（2025 年 1 月）的规则类别整理：9 个部分、53 条写作规则，涉及选词、语法、句子结构和风格。详见 [规则参考](references/writing-rules.md)。

本技能未收录官方约 900 个批准词语的词典，也没有逐词验证其批准词义和词性。标准可免费申请，但不代表可以自由再发布；上游指出，第 9 版第 2 页只向列出的八类组织授予免费复制权，其他复制或出版需要 ASD 书面授权。

因此，本技能能够按说明检查结构，但选词只能遵循“常用、简单、前后一致”的原则。需要精确的航空维修合规文本时，应通过 [官方申请页面](https://www.asd-ste100.org/STE_downloads.html) 获取标准并逐词核对；该页面是发送下载链接的申请表，不是直接下载地址。

## 核心改写规则

### 结构规则

| 规则 | 建议写法 | 避免的写法或原因 |
|---|---|---|
| 主动语态 | “The agent deletes the file.” | 操作步骤使用主动语态；描述性文本仅在执行者未知或无关时允许被动语态 |
| 不用短语动词（规则 9.3） | “Remove the panel.” / “Start the job.” | “Take off the panel.” / “Spin up the job.”；组合后的含义不能从单词直接推断 |
| 每句一条指令 | “Open the file. Read line 3.” | 一句同时包含打开、读取、检查等多项操作 |
| 句长 | 操作步骤每句不超过 20 个英文词；描述每句不超过 25 个词 | 过长的并列句或层层嵌套的从句 |
| 不用分号（规则 8.1） | 拆成独立句子 | STE 禁止分号本身；其他标准标点，包括长破折号，并未被禁止 |
| 名词堆叠 | 连续组成名词短语的词不超过 3 个，如 “fuel pump valve” | “high pressure fuel pump inlet valve assembly” 等长串修饰词 |
| 不省略句子成分 | 明确写出主语、动词和冠词 | 为省字删除这些成分，导致指代或条件不清 |
| 保留确定程度 | “The request **may have** failed.” | 不能改成 “The request failed.”；“可能”与“已经”是不同事实判断 |
| 段落 | 每段一个主题，最多 6 句 | 一段混合多个主题 |
| 操作序列 | 3 项及以上步骤或条件使用列表 | 把步骤或复杂条件埋在一个长句中 |

### 词汇规则：作为建议，不能声称官方词典合规

| 规则 | 做法 | 限制 |
|---|---|---|
| 一词一义 | 同一动作尽量固定用词，例如始终用 “check”，不要随意轮换 “verify” 和 “confirm” | 可以检查文内一致性，无法凭本技能确认哪个词获官方批准 |
| 一个词只用一种词性 | 优先 “Apply oil to the valve.”，而非 “Oil the valve.” | “oil” 是否只获批准作名词，必须查官方词典 |
| 用动词表达动作（规则 3.7） | “Analyze the log.”，而非 “Perform an analysis of the log.” | 偏好直接动词可执行；具体动词是否获批准仍需词典 |
| 领域术语 | 必要的技术名词和动词保留；首次说明含义，必要时补一行术语表 | STE 允许扩展领域术语表，但本技能未收录其基础词典 |

### 简单时态及例外

STE 允许不定式、祈使句、一般现在时、一般过去时、一般将来时和作形容词的过去分词。它通常排除现在完成时等复合形式，例如偏好 “We received the report.”，而非 “We have received the report.”。

但状态报告可能需要表达“过去完成且当前仍有影响”，也可能需要保留 “may have failed” 的不确定性。**如果简单形式无法保留原意，保留复合形式，并说明偏离规则的原因。确定程度优先于时态简化。** 不要为了合规把“可能失败”改成“失败”。

## 改写前检查

1. **同义词轮换**：同一对象同时叫 “user”“customer”“client”，会让读者误以为是多个对象。确认确为同一对象后统一称呼。
2. **限定语堆叠**：“it is important to note that this may potentially help to improve”。去除空话，但保留表达真实不确定性的 “may”“could”“sometimes”等信息。
3. **名词化**：用 “analyze”“helps”，代替 “perform an analysis of”“provides assistance to”。
4. **营销形容词**：“seamless”“robust”“powerful”“cutting-edge”等。删除无依据的质量宣称，或用来源中已有的测量结果替代；不能编造数据。
5. **长句连缀**：多个观点用分号或破折号串联。按含义拆句，保留原有条件和关系。
6. **含义不直观的短语动词**：“spin up”“reach out”“dive into”“kick off”。按实际含义改为 “start”“contact”“read”“begin”。

## 工作流程

1. 在内部选择严格模式或参考 STE 模式。
2. 先读懂原文，确定改写后必须保留的事实、条件、范围和确定程度。
3. 逐句检查上述规则。参考 STE 模式只提示词汇问题，不强制固定词汇。
   - 可用 `uv run --no-project scripts/ste-lint.py <文件>` 做初步检查。该脚本仅依赖 Python 标准库；路径相对于本技能目录，其他目录运行时使用绝对路径。
   - 支持从标准输入读取；`--json` 输出结构化结果；`--baseline N` 容许 N 个硬性问题；`--disable rule1,rule2` 停用指定规则。
   - 检查范围包括分号、句长、部分短语动词、名词化、营销词、同义词轮换、支持的列表中悬空的连词、被动语态和复合时态。悬空连词指列表项以 “and” 或 “or” 结尾，却缺少后续内容。
   - 脚本不把表达不确定性的词当作违规，不验证改写前后是否等义，也不验证官方词典合规。检查通过只表示已配置的模式未发现问题。
4. 修复问题，同时保留原意。如果简化会丢失安全条件、范围、数字或其他必要精度，保留原句并说明原因。
   - 改写前再次核对 “may”“could”“sometimes”“is likely to” 等表达；置信程度属于内容。
   - 不增加原文没有的原因、频率、机制、建议或事实。用户另行要求补充建议时，将新增内容明确标出。
5. 按下述格式输出；默认不展示内部模式选择和分析。
6. 原文已符合要求时，直接说明，无须强行修改。可用中文说明检查结果。

## 输出格式

**默认只输出改写后的英文正文。** 不加技能介绍、模式说明、违规数量、修改总结、规则表或结尾邀约。

如果为保留必要精度而刻意保留较长表达或复合时态，可在正文后加一行：`保留原表达：`，指出表达及理由。没有保留项时不添加。词汇合规限制应在用户要求合规结论时说明，不凭结构检查给出官方合规保证。

**用户要求解释或前后对照时**，使用中文表头，原句与改写句保持英文：

```markdown
| 涉及规则 | 原文 | 改写后 |
|---|---|---|
| 现在完成时 | “We have received your request.” | “We received your request.” |
| 名词堆叠（4 个及以上词） | “the agent task queue priority handler” | “the handler that sets task-queue priority” |

模式：严格模式。发现 7 处问题。
```

表格后用一行说明刻意保留的表达及原因。示例中的时态修改只适用于不丢失“当前仍相关”含义的情况，不能机械替换。

## 边界

- 保留所有事实、条件、范围和不确定性；不能通过缩短句子改变判断。
- 不复刻或声称背诵官方词典；精确批准用词以官方标准为准。
- 不保证航空航天或国防级 STE 合规。本技能是借鉴 STE 的通用英文清晰度工具。
- 不把空洞内容改写成有依据的结论。原文缺少实质信息时，应指出缺口。
- 以消除歧义为目标，不追求最短句子；压缩损害清晰度时停止。
